# Dependencies for the `f1-agent` Cloud Run service.
#
# Kept separate from backend/requirements.txt on purpose: this tree is large
# (LangChain + LangGraph + deepagents) and would roughly double the API image
# for code the API never runs. That size difference is the main reason
# CHAT-AGENT-PLAN.md §12 makes this a separate service rather than more routes
# on f1-backend.
#
# Versions are pinned with `~=` (compatible-release): patch updates flow, minor
# ones do not. An agent stack that silently moves a minor version between two
# deploys is how a working service becomes a broken one with no diff to blame.

# --- Service ---------------------------------------------------------------
fastapi~=0.141.1
uvicorn~=0.52.1
pydantic~=2.13.4
httpx~=0.28.1
python-dotenv~=1.2.2

# --- Data (shared with backend/app, which the agent tools call directly) ----
# motor's last release is 3.7.1 — it is in maintenance now that pymongo ships
# its own async API. Pinned to what exists rather than to what looks current;
# an invented version number aborts the whole install with a resolver error
# that names only the one bad line.
motor~=3.7.1
# NOT 4.17: `langgraph-checkpoint-mongodb` 0.4.0 requires `pymongo<4.17,>=4.12`,
# and that ceiling is invisible until the resolver runs. Raising this pin makes
# the whole install unsatisfiable, so if a future bump is needed, check the
# checkpointer's constraint first.
pymongo[srv]~=4.16.0

# --- Agent stack -----------------------------------------------------------
# deepagents 0.7.4 is the version CHAT-AGENT-PLAN.md was written against, and
# it brings langchain/langgraph with it; both are pinned anyway so a resolver
# change cannot move them underneath us.
deepagents~=0.7.4
langchain~=1.3.0
langgraph~=1.2.0
langchain-ollama~=1.1.0

# CP62. Installed now so the image is built and deployed once, not rebuilt with
# a new dependency tree in the middle of a checkpoint.
langchain-tavily~=0.2.18

# CP61's thread memory. The plan flags a real risk here: the async saver's
# import path moved in LangGraph 1.0. `agent/spikes/checkpointer_spike.py`
# checks it, and the fallback is a hand-rolled Mongo thread store.
langgraph-checkpoint-mongodb~=0.4.0

# --- Observability ---------------------------------------------------------
# LangGraph traces natively; this is here for the explicit CP59 spans and for
# the run ids the CP65 feedback loop is keyed on.
langsmith~=0.11.0
